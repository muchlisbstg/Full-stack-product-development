## Status semantics
- `NOT_INSTALLED`: artifact absent; `NOT_EVALUATED`: repository not evaluated.
- `NOT_VERIFIED`: evidence absent/insufficient; `PARTIAL`: only evidenced controls implemented.
- `IMPLEMENTED`: required controls inspected; `TESTED`: named tests passed on recorded commit/environment.
- `APPROVED`: authorized governance owner recorded approval.

**Fail closed:** missing evidence is never PASS. A file, workflow definition, diagram, or test script alone does not prove execution or compliance.

## Evidence contract
Every evaluation must record repository/path, branch, full commit SHA, Actions run/job, artifact URL and SHA-256, test command/environment/timestamp/result, scope, reviewer and approval reference.

## Governance boundaries
- Installing this registry does not implement or certify the six SDLC domains.
- License remains `NOT_VERIFIED` until LICENSE file and terms are inspected.
- Maintenance remains `NOT_VERIFIED` until commit/release/issue evidence is collected.
- Candidate runtime PASS requires retained execution evidence.
- No application source, schema, migration, secret, staging resource, deployment, or production configuration is changed.
- Draft PR only; manual review and explicit approval are required before merge.

## Change control
Any scope, schema, status, or taxonomy change requires a versioned update reconciled across all 27 distributed copies. `ewallet-platform` is outside this 27-repository registry scope and is not modified.
